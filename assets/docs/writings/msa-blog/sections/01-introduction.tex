\section{Sparse Attention 的几种模式}

标准 attention 要算所有可见的 query-key 交互，长序列下计算量随长度平方增长； FlashAttention 省掉了中间矩阵的读写，但交互本身一个没少\hyperlink{ref-1}{\textsuperscript{[1]}}。 Sparse attention 只让每个 query 看一部分 keys。图 1 列了几种常见做法： 有按位置固定的局部窗口、sinks 和 global tokens\hyperlink{ref-2}{\textsuperscript{[2]}}\hyperlink{ref-3}{\textsuperscript{[3]}}\hyperlink{ref-4}{\textsuperscript{[4]}}\hyperlink{ref-5}{\textsuperscript{[5]}}， 也有按内容动态选择的 token 或 block\hyperlink{ref-6}{\textsuperscript{[6]}}\hyperlink{ref-7}{\textsuperscript{[7]}}\hyperlink{ref-8}{\textsuperscript{[8]}}。

对 kernel 来说，关键是\textbf{不同 query 的选择是否相同}。 图 (e) 里一组 query 共用同一块 mask，选中区域天然是规整的矩阵； 图 (f) 里每个 query 单独选块，相邻两行未必选到同一块。本文讨论后一种。

MiniMax Sparse Attention（MSA）就是一个例子：先由一个轻量分支为每个 query 选出若干 KV 块， 再在选中的块上计算 attention\hyperlink{ref-9}{\textsuperscript{[9]}}。本文只讨论第二步的训练前向，选块结果视为已知。

还需要一点 GQA 的背景\hyperlink{ref-10}{\textsuperscript{[10]}}：$G$ 个 query heads 共用一份 K/V， 同一 token 的这 $G$ 个 heads 也共用同一份选块列表。 每个 KV 块包含 $B_k$ 个 token，所以一个 query 和一个块之间的 QK 是一个 $G\times B_k$ 的小矩阵。

\section{遇到的问题}

一个 query 和一个块之间只有 $G\times B_k$ 的小矩阵，而 $G$ 通常很小。设计 kernel 时，为了使设计的 kernel 有较好的性能，以下三件事是比较重要的：

\begin{itemize}
\item \textbf{填满 Tensor Core。}MMA 指令对矩阵形状有下限，$G$ 行远远不够，不足的部分只能 padding。
\item \textbf{复用 K/V。}不同 query 常常选到同一个块，每个 query 各读一次，读取量会成为瓶颈。
\item \textbf{不做多余的工作。}被 mask 掉的计算、局部结果的写出和合并、额外的索引，都会抵消前两项的收益。
\end{itemize}

然而以上三个条件在逐 Query Sparse Attention 中很难全部满足，首先看一个最小的例子：$q_0$ 选了 KV 块 A、B，$q_1$ 选了 B、C。 两个 query 分开算，B 要读两次，矩阵也只有 $G$ 行；放在一起算，B 只读一次，矩阵也变高了， 但这一组要把 A、B、C 都算一遍，其中 $q_0$ 对 C、$q_1$ 对 A 的结果最后都会被 mask 掉， 计算量从 4 个 query-block 对变成了 6 个。

换成 kernel 的语言，取舍体现在：这些小矩阵交给哪个线程块（CTA）计算？ 图 2 画了三种划分： (a) 一个 CTA 负责一个 query；(b) 一个 CTA 负责几个相邻 query，遍历它们选块的并集； (c) 一个 CTA 负责一个 KV 块，处理所有选中这个块的 query。
